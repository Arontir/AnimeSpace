# AnimeSpace

Веб-платформа для перегляду аніме: каталог із пошуком і фільтрами, сторінка тайтлу з вбудованим плеєром, особисті списки («Дивлюсь», «У планах», «Переглянуто», «Покинуто»), оцінки та коментарі, панель адміністратора.
Дипломний проєкт на **ASP.NET Core MVC (.NET 11)** за принципами чистої архітектури.

## Можливості

**Глядач**
- Реєстрація та вхід (ASP.NET Core Identity).
- Каталог: пошук за назвою, фільтри за жанром, роком і статусом (онгоїнг / завершено), сортування, пагінація.
- Сторінка тайтлу: опис, жанри, середня оцінка, відеоплеєр, коментарі. Для плейлистів YouTube під плеєром з'являються кнопки серій.
- Оцінювання (1–10), коментарі та особисті списки без перезавантаження сторінки (fetch).
- Особистий кабінет: списки за вкладками, зміна статусу, видалення.

**Адміністратор**
- Статистика сайту.
- Керування тайтлами: створення, редагування, видалення, завантаження постера, посилання на плеєр, жанри.
- Керування жанрами.
- Видалення будь-яких коментарів.

## Архітектура

Чотири проєкти плюс тести. Залежності спрямовані до центру:

```
Web  ──►  Application  ──►  Domain
 │             ▲
 └──►  Infrastructure ──┘
```

| Проєкт | Відповідальність |
|---|---|
| `AnimeSpace.Domain` | Сутності (`Anime`, `Genre`, `Bookmark`, `Comment`, `Rating`, `ApplicationUser`), переліки, константи. Не залежить від інших проєктів. |
| `AnimeSpace.Application` | Бізнес-логіка: сервіси, DTO, інтерфейси репозиторіїв і сховища файлів, перетворення сутностей у DTO, виключення. Не знає про EF Core, SQL і ASP.NET. |
| `AnimeSpace.Infrastructure` | Реалізації: `DbContext`, конфігурації та міграції EF Core, репозиторії, збереження файлів, початкове наповнення бази. |
| `AnimeSpace.Web` | Контролери, представлення, JSON-ендпоїнти, область `Admin`, `Program.cs` (збирає всі шари разом). |
| `AnimeSpace.Tests` | Юніт-тести сервісів (Moq) та інтеграційні тести репозиторіїв (SQLite). |

Відповідність вимогам до шарів: Domain = Core, Infrastructure = Data, Application = Services, Web = Web.

## База даних

Таблиці: `Animes`, `Genres`, `AnimeGenres` (зв'язок «багато-до-багатьох» тайтлів і жанрів), `Bookmarks`, `Comments`, `Ratings` та стандартні таблиці Identity.

- `Bookmarks` — зв'язок «користувачі ↔ тайтли» зі статусом; пара (користувач, тайтл) унікальна.
- `Ratings` — одна оцінка користувача на тайтл (унікальний індекс), обмеження значення 1–10 (CHECK).
- Індекси: за назвою тайтлу, за рейтингом, за (тайтл, дата) у коментарях, унікальна назва жанру.
- Зовнішні ключі з каскадним видаленням.
- `Animes.AverageRating` і `RatingsCount` — свідома денормалізація (збережений підсумок для швидкого каталогу), джерело істини — таблиця `Ratings`; значення перераховується одним запитом UPDATE у базі.

## Запуск

### Вимоги
- .NET 11 SDK
- SQL Server (на Windows підійде LocalDB, що встановлюється разом з Visual Studio). На Linux/macOS — SQL Server у Docker.

### Кроки

1. Клонувати репозиторій.
2. Перевірити рядок підключення в `src/AnimeSpace.Web/appsettings.json` (секція `ConnectionStrings:DefaultConnection`). Для SQL Server у Docker використайте, наприклад:
   `Server=localhost,1433;Database=AnimeSpaceDb;User Id=sa;Password=<пароль>;TrustServerCertificate=True`
3. Пошта адміністратора береться з `Seed:AdminEmail` у `appsettings.json`. Для режиму розробки в `appsettings.Development.json` можна ввімкнути `Seed:SeedDemoData` (демонстраційні тайтли).
4. Запустити:
   ```bash
   dotnet run --project src/AnimeSpace.Web
   ```

Під час першого запуску застосунок сам застосує міграції, створить базу, роль `Admin`, обліковий запис адміністратора та базові жанри. Окремої команди для створення бази не потрібно.

### Тести

```bash
dotnet test
```

### Нова міграція (для розробників)

```bash
dotnet ef migrations add <Назва> -p src/AnimeSpace.Infrastructure -s src/AnimeSpace.Web -o Persistence/Migrations
```

## Відеоплеєр

У кожного тайтлу одне поле `PlayerUrl`: посилання на вбудований плеєр (iframe) для всього тайтлу. Сайт не прив'язаний до конкретного сервісу: підійде будь-яке посилання `https`.

- **YouTube-плейлист** (рекомендовано для демонстрації): `https://www.youtube.com/embed?listType=playlist&list=<ID плейлиста>`. Для таких посилань сторінка тайтлу будує кнопки серій через YouTube IFrame API (`youtube-playlist.js`). Потрібен плейлист, власник якого дозволив вбудовування.
- **Інші плеєри**: серії й озвучки перемикаються всередині самого плеєра.

## Безпека

- Захист від CSRF: перевірка токена в усіх небезпечних запитах, для `fetch` токен передається в заголовку.
- Захист від XSS: Razor екранує виведення, динамічні коментарі додаються через `textContent`.
- Завантаження файлів: білий список розширень, випадкове ім'я файлу, обмеження розміру, фіксована папка.
- Авторизація: `[Authorize]` для особистих дій, роль `Admin` для адмінки; для AJAX повертаються коди 401/403.
- Запити до бази параметризуються EF Core; спецсимволи в пошуку екрануються.
- Бізнес-правила перевіряються в сервісах незалежно від форми (посилання на плеєр лише `https`, діапазон оцінки, довжина коментаря).
